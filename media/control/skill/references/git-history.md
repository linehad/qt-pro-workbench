# Git history in VS Code and Qt Pro

Qt Pro 0.12.5+ can inspect repository and individual source history without opening workspace folders. For an API connection read [projects.md](projects.md), choose the window by its actual project path, then use the installed bridge `help` for current schemas. History commands keep the active build project and debugger unchanged.

## Read history from Codex

- `qt_git_history`: specify absolute `file` for file history including renames, or an absolute directory (0.12.9+) for all descendant file changes. Directory results include `directoryPath` and each commit's scoped `changes` list. Alternatively specify `projectPath` for repository history; omitting both uses the active project's repository. `skip` starts at 0, `limit` is 1–200. Continue with `nextSkip` when `hasMore` is true.
- Each entry includes `hash`, `parents`, `date`, `author`, `subject`; file history also returns `filePath`, `previousPath` and `change`. These paths belong to the returned `repositoryRoot`. File history is not the same as all repository commits.
- `qt_git_read_revision`: pass the original absolute `file`, an entry's full `hash` as `revision`, and its `filePath` as `historicalPath`. This preserves repository identity when a file was renamed. To inspect the preceding version, use `parents[0]` and `previousPath`. For an added file there is no earlier source; for a deletion there is no source at the deleting commit.
- For textual comparisons, use the exact root and paths from the result with supported Git CLI, for example `git -C <root> diff <hash>^ <hash> -- <path>`. A rename comparison includes the old and new paths. A root commit has no parent; use `git show` or compare its source against empty content.

Do not activate another project just to read its history. A Work project and a Main project with identical file names have separate histories; use the requested full path. A plain copied folder or downloaded ZIP without `.git` has no local commit history. Report that condition; clone the intended repository only when requested. Reading history does not request checkout, reset, revert, merge, commit or push.

## Show history to the user

- `qt_git_show_graph` opens Git Graph for `projectPath` or the active project. It returns the resolved root and uses Git Graph's command directly, without adding folders or opening another VS Code window.
- `qt_git_show_file_history` takes an absolute `file` and opens or reveals a persistent SVN-style log tab (0.12.8+). The table shows commits, change type, author, date and subject; the lower panes show the full selected message and changed path. Double-click a commit, click its changed file, or choose **수정 전 / 수정 후 비교** to open the existing VS Code diff: before on the left, after on the right. **현재 파일과 비교** and **이 버전의 소스 보기** remain available. Search/date filters cover loaded entries; use **이전 이력 더 보기** for older pages. For unattended investigation use the read operations above.
- `qt_git_open_diff` opens a comparison directly, without a picker: pass `file`, a full `revision` hash and that entry's `filePath` as `historicalPath`. Default `comparison: "previous"` shows the commit's change, including renamed sources. `comparison: "working"` compares that revision against the current file, including unsaved edits.
- `qt_git_open_revision` opens the specified `file` / `revision` / `historicalPath` directly as a read-only source document.
- `qt_git_compare_latest` (0.12.9+) takes an absolute `file` and opens HEAD on the left against the current local source on the right, including unsaved edits. It reads the file's own repository HEAD each time; it does not depend on the selected log row. The same action is **최신 커밋과 비교** in file context menus and the log tab. In a directory log, choose a changed file first.
- In Qt Projects, right-click a project → **Git Graph 보기**. Right-click a source/header/project/include file or a folder → **Git 이력 조회**. The command is also available in editor and Explorer context menus. Folder logs cover only descendants in that repository and list every scoped changed path; click a path for its before/after diff. With multiple changed files, choose the desired path rather than assuming the first file.
- Project and `.pri` containers in the tree query their containing directory (0.12.10+); their child `.pro`/`.pri` file rows query that file alone. The log header identifies the scope as file or folder with its full path. Click the start/end date field itself to open the calendar (0.12.12+), select year/month/day, or use Today/Clear. Valid `YYYY-MM-DD` typing and Alt+Down keyboard access also work. Date filters still cover loaded history pages only.
- Log panes are resizable (0.12.11+): drag the separators between commits, message and changed files. Ratios persist within that log tab and adapt to window height; double-click a separator to reset. Keyboard Up/Down also adjusts a focused separator. The changed-file heading shows the full count; scroll or enlarge the pane for longer lists rather than assuming hidden rows are missing data.
- Revision views use read-only `qt-pro-git:` documents. Comparing with the current file preserves its unsaved text; viewing history never overwrites working files. Source decoding uses the original file bytes, open document encoding and `files.encoding`, with BOM/UTF-8/UTF-16 and legacy CP949/EUC-KR detection. Historical revisions can have different Unicode encoding; no working file is converted.

Git Graph is an extension dependency (`mhutchie.git-graph`); Git itself must be installed or configured through `git.path`. Project graph shows the whole repository containing that project. Native Source Control/Timeline may still require workspace discovery, so use these Qt Pro commands in folderless windows.
